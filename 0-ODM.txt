==============================5-Create Collection with options
| Option                | Type                                      | Description                                                |
| --------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| `collection`          | `String`                                  | Specify the name of the collection                         |
| `timestamps`          | `Boolean` or `{ createdAt, updatedAt }`   | Automatically adds `createdAt` and `updatedAt` fields      |
| `versionKey`          | `Boolean` or `String`                     | Adds a `__v` field to track versioning (default `true`) 
             									and  can change key name versionKey :"version"   |
|optimisticConcurrency  | true                                      | to allow key version update only work with  the save
| `strict`              | `Boolean` or `"throw"`                    | Only values in the schema are saved (default `true`)       |
| `strictQuery`         | `Boolean`                                 | Controls query casting (default `false`)                   |
| `capped`              | `Boolean` or `{ size, max, autoIndexId }` | Creates a capped collection                                |
| `autoIndex`           | `Boolean`                                 | Automatically builds indexes on startup  if false then  UserModel.syncIndexes()|               
| `id`                  | `Boolean`                                 | Adds virtual `id` getter of `_id.toString()` not must apply toJson and toObject|               
| `_id`                 | `Boolean`                                 | If `false`, disables the automatic `_id` field             |
| `minimize`            | `Boolean`                                 | Removes empty objects from output (default `true`)         |
| `toJSON` / `toObject` | `Object`                                  | Custom behavior for `.toJSON()` / `.toObject()`            |
| `validateBeforeSave`  | `Boolean`                                 | Whether to run validators before `save()` (default `true`) |

=========================================================mongo session in replica mode only

const session = await mongoose.startSession();
session.startTransaction();

try {
  await UserModel.insertMany(users, { session });
  await session.commitTransaction();
  console.log("Transaction committed!");
} catch (err) {
  await session.abortTransaction();
  console.error("Transaction aborted:", err.message);
} finally {
  session.endSession();
}
====================================================UPDATE
| Option                | Type                    | Description                                                                                    |
| --------------------- | ----------------------- | ---------------------------------------------------------------------------------------------- |
| `new`                 | `Boolean`               | If `true`, returns the updated document instead of the original (used with `findOneAndUpdate`) |
| `upsert`              | `Boolean`               | Creates a new document if no match is found                                                    |
| `runValidators`       | `Boolean`               | Runs schema validation on the update                                                           |
| `timestamps`          | `Boolean`               | Updates `createdAt` and `updatedAt` fields (if `timestamps` is enabled in schema)              |
| `overwrite`           | `Boolean`               | If `true`, completely replaces the document (used with `update`)                               |
| `returnDocument`      | `"before"` \| `"after"` | Replaces `new: true` (newer syntax)                                                            |
| `setDefaultsOnInsert` | `Boolean`               | Applies default values when `upsert` is true                                                   |
| `context`             | `"query"` \| `"update"` | Needed for some validators to work properly                                                    |
